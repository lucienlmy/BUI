A box that slides in with an elastic ease, a timeline of three steps, a card that springs when you hover it: **GSAP's and Motion's APIs, run by BUI.** You import `gsap` or `motion`, call them as you would anywhere, and the animation runs in BUI's engine. JavaScript hands over each call's values once, and hears from the engine only for the callbacks you ask for.

## GSAP

```js
import { gsap } from '@blender-ui/native/gsap'

gsap.to('.box', { x: 200, duration: 1, ease: 'elastic.out(1, 0.3)', stagger: 0.1 })
gsap.from('#title', { opacity: 0, y: 20 })
gsap.fromTo(el, { scale: 0.8 }, { scale: 1, ease: 'back.out(2)' })

const tl = gsap.timeline({ repeat: 1, yoyo: true, defaults: { duration: 0.5 } })
tl.to('#a', { width: 100 })
  .to('#b', { width: 100 }, '<0.2')      // GSAP's position strings
  .addLabel('mid')
  .to('#c', { opacity: 0.2 }, 'mid+=0.25')

const t = gsap.to(el, { x: 100, onComplete () { console.log('done') } })
t.pause(); t.seek(0.5); t.reverse(); t.progress(0.25)
await t // resolves when it ends
```

- **Targets:** selectors (`'#id'`, `.class`, `tag`, `[attr=v]`), elements, motion values, or one plain object, whose numbers are tweened and written back each frame.
- **Properties:** `x`, `y`, `scale`, `rotate`, `opacity`, and any CSS property that interpolates.
- **Options:** `duration`, `delay`, `ease`, `repeat`, `repeatDelay`, `yoyo`, `stagger`, `paused`, `reversed`, `overwrite`, `immediateRender`, `timeScale`, and the callbacks `onStart`, `onUpdate`, `onComplete`, `onRepeat`, `onReverseComplete`, `onInterrupt`.
- **Overwrite:** a new tween on a property takes over from the old one and keeps its velocity.

## Motion

```js
import { animate, motionValue, stagger } from '@blender-ui/native/motion'

animate('.card', { opacity: 1, y: 0 }, { duration: 0.4, delay: stagger(0.05) })
animate(el, { x: 100 }, { type: 'spring', stiffness: 300, damping: 20 })

const x = motionValue(0)
animate(x, 100, { type: 'spring', bounce: 0.25, duration: 0.5 })
animate(0, 100, { onUpdate: v => console.log(v) })
```

Any element takes Motion's props with `setMotion`:

```js
el.setMotion('initial', { opacity: 0, y: 20 })
el.setMotion('animate', { opacity: 1, y: 0 })
el.setMotion('whileHover', { scale: 1.05 })
el.setMotion('transition', { type: 'spring', stiffness: 400, damping: 30 })
el.setMotion('drag', 'x')
el.setMotion('layout', true)
el.style = { x: motionValue(0) }        // a motion value bound to a property
```

The props are `initial`, `animate`, `exit`, `whileHover`, `whileTap`, `whileFocus`, `whileInView` (with `viewport`), `whileDrag`, `transition`, `variants`, `drag` (`true`, `'x'`, `'y'`) with `dragConstraints`, `dragElastic`, `dragMomentum` and `dragSnapToOrigin`, and `layout` (`true`, `'position'`, `'size'`). `setMotion(name, null)` removes one, and an unknown name throws.

## In React

```jsx
import { motion, useMotionValue, useSpring, useTransform } from '@blender-ui/react/motion'

<motion.div initial={{ opacity: 0, y: 20 }} animate={{ opacity: 1, y: 0 }}
            whileHover={{ scale: 1.05 }} transition={{ type: 'spring', stiffness: 400 }} />
```

- **Host elements:** `motion.div`, `motion.span` and the rest take the props above; `motion.Button`, `motion.NumberSlider` and the other Blender widgets animate their own values.
- **Motion values:** `style={{ width: mv }}` follows a value without rendering the component again.
- **Exit animations:** an element with an `exit` that you remove stays and animates out before it goes; `AnimatePresence` passes its children through.
- **Not there yet:** `layoutId`.

## Springs and eases

`type: 'spring'` is a real spring: the engine solves the damped spring equation in closed form, for the underdamped, critically damped and overdamped cases. A frame reads the value at its time, so the frame rate doesn't change the result, and interrupting a spring hands its position and velocity to the next motion. Give `stiffness`, `damping` and `mass`, or `duration` and `bounce`. `type: 'inertia'` decays from a velocity.

Every ease of GSAP, Motion, CSS and Blender works by name: `'none'`, `'power2.out'`, `'sine.inOut'`, `'expo.out'`, `'back.out(1.7)'`, `'elastic.out(1, 0.3)'`, `'bounce.out'`, `'steps(4)'`, `'easeInOut'`, `'anticipate'`, `'cubic-bezier(0.2, 0.8, 0.4, 1)'`, a `[x1, y1, x2, y2]` array, or a name you registered with `CustomEase`.

## Web Animations

`el.animate(keyframes, options)` runs for real, on the same engine.

## Testing animations

A headless app's clock stands still. Move it by hand to check a value frame by frame:

```js
const app = new App({ headless: true })
// ...open a window, start an animation...
await app.advanceClock(500)   // half a second later, every window has rendered that frame
```

## Limits

- **Widgets:** a Blender widget has no draw transform or opacity; `x`, `y`, `scale`, `rotate` and `opacity` apply to HTML elements. A widget animates its own values.
- **QuickJS:** `bui build` without `--bun` runs on QuickJS, where the animation API is unit-tested but has had less use than on Node and Bun.
